# Database

## In scope
`directory/models.py`, `directory/migrations/`, indexes, constraints, data migrations, `contact/models.py`. **Out:** views (backend), UI.

## Rules
- Status: `CharField` with explicit choices, default `pending`; expose constants once (`Website.STATUS_PENDING` ...) and reuse them.
- Ratings are integers 1-5; `Rating(website, user)` unique. Prefer `UniqueConstraint` and `CheckConstraint(1..5)` in new code.
- Slug: unique, generated in `save()` once (not rewritten on every save); Persian-safe via `allow_unicode=True`; MySQL index length for utf8mb4 (`max_length=220` unique is within InnoDB limits; verify).
- `average_rating` / `total_ratings` change only through `Website.update_rating()`; compute with the DB (`aggregate(Avg, Count)`), not Python sums.
- Indexes for `status`, `created_at`, `category`, slug; `Website(status, -created_at)` for the index query.
- Dates are timezone-aware Gregorian; Jalali is display-only.
- Every schema change ships with one migration generated by `makemigrations`. Never hand-undo a previous migration (0003 added Persian verbose names and 0004 removed them: squash or re-add the names in `models.py` so state matches).
- Production MySQL is `utf8mb4`; test migrations on MySQL, not only SQLite.
