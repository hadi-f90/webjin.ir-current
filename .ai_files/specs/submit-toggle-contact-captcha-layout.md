# Spec: Submission Details Toggle and Contact Captcha Alignment

## Problem Statement
Anonymous visitors report that the optional-details section on the public website submission form does not reliably expand and collapse in Microsoft Edge, and that the contact-page captcha image and answer input are not aligned like those on the submission page. These defects make form completion harder; their runtime causes have not yet been confirmed.

## User Stories
1. As an anonymous visitor, I want the optional details on the public submit form to open and close reliably in Microsoft Edge, so that I can reveal or hide those fields while submitting a website.
   - Acceptance criteria:
     - [ ] In the current stable Microsoft Edge release, while logged out and with the production Content Security Policy active, the optional-details section starts closed, opens on activation of its control, and closes on the next activation.
     - [ ] The same toggle remains functional after a validation response rerenders the public submit form.
     - [ ] The control’s expanded state and the section’s visibility stay synchronized, and the closed section’s controls are not keyboard-focusable.
     - [ ] The toggle produces no browser-console JavaScript or Content Security Policy error that prevents its behavior.
2. As a visitor, I want the contact-form captcha image and answer input to align like the submission-page captcha, so that I can read and enter the challenge easily.
   - Acceptance criteria:
     - [ ] On the contact page at viewport widths of 576 CSS pixels and wider, the captcha image and answer input appear on one horizontal line, vertically centered, with a visible gap comparable to the submission page.
     - [ ] At viewport widths of 320, 375, and 576 CSS pixels, the captcha image and answer input remain fully visible and usable, and the page has no horizontal overflow caused by the captcha; when the available width is insufficient, the elements may wrap or stack.
     - [ ] The alignment and responsive checks pass in RTL layout, with both a fresh captcha and a rerendered form containing captcha validation feedback.

## Evidence and Probable Causes
- **Submission toggle — confirmed cause:** the original click handler was inline, while the effective CSP blocks inline scripts. Replaced the clickable `div` with a semantic button and moved the handler to `static/js/submit-details.js`.
- **Submission validation:** if an optional-details field has a validation error, the server-rendered response now opens the details panel and marks the button expanded.
- **Contact captcha:** the rendered crispy widget contains a fieldset, challenge image, and answer input. Contact-specific CSS aligns them in a row when space permits and allows wrapping on narrow screens.
- **Static cache:** the browser retained an older `custom.css` response at the unchanged URL during verification. The stylesheet URL now has a version query so browsers fetch the updated layout.

## In Scope
- Reliable open/close behavior for the optional details panel on the anonymous public submit form in Edge.
- Horizontal alignment and responsive behavior of the captcha image and answer input on the contact form.
- Verification of the above against the existing RTL presentation and effective CSP.

## Out of Scope
- Changing captcha policy, provider, or validation behavior.
- Changes to website/contact submission processing, fields, moderation, or AJAX response contracts.
- Redesign of either form or unrelated browser, accessibility, or security work beyond what is necessary for these two defects.
- Changes to authenticated submission behavior except where shared toggle behavior must remain functional.

## Assumptions
- The public submit page remains the visual reference for the captcha image/input relationship.
- The report describes user-observed defects, not a confirmed browser reproduction or diagnosed root cause.
- Captcha markup is generated by the configured django-simple-captcha widget and may vary with its installed version or settings; acceptance checks target the visible image and answer control rather than a particular HTML structure.

## Verification
- Django submit/contact tests passed (10 tests); the new regression test confirms validation errors inside the optional details open that section.
- `node --check static/js/submit-details.js` and `git diff --check` passed.
- Chromium browser checks confirmed captcha alignment at 576 CSS pixels, wrapping without horizontal overflow at 320 and 375 pixels, and alignment remains correct after an AJAX captcha validation error.
- The browser checks were not run in Microsoft Edge. Edge-specific acceptance criteria therefore remain unverified.
